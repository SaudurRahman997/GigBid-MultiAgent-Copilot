# ADR 0001: Default technology stack

- Status: accepted
- Date: 2026-11-15

## Context
GigBid needs agents, MCP servers, an API, a web UI, a vector store, a queue and tracing, and has to run
on a laptop and on one small VM with `docker compose up`.

## Decision
We use the defaults from BUILD_SPEC section 3 unless a later measurement says otherwise:

| Area | Choice |
|---|---|
| Python | 3.12 (pinned via `.python-version`), uv, exact pins in `pyproject.toml` + `uv.lock` |
| Agents | LangGraph StateGraph + Postgres checkpointer + LangGraph store |
| MCP | official MCP Python SDK (FastMCP); `langchain-mcp-adapters` in the agent |
| API | FastAPI + Pydantic v2, SSE |
| Web | Next.js 16 (App Router) + TypeScript, client generated by openapi-typescript |
| DB | Postgres 16 + pgvector (only vector store), Redis |
| Worker | Arq |
| Tracing | Arize Phoenix (self-hosted) |
| LLMs | Ollama Qwen3 locally; Groq/OpenRouter gpt-oss for the deployed link |
| Embeddings / reranker | BGE-M3, bge-reranker-v2-m3 (CPU) |
| E2E | Playwright |
| Deploy | one Linux VM, docker compose, Caddy |

Python 3.12 rather than the machine default 3.14: several ML dependencies (torch,
sentence-transformers) ship wheels for 3.12 first.

## Consequences
One compose file describes the whole system, so local, CI and deployed stacks match. Changing any
choice needs a new ADR that cites a measurement in `evals/results/`.
