# Deploying GigBid

Two public pieces:

| Piece | Host | Source |
|---|---|---|
| Web UI (Next.js) | Vercel | `apps/web` |
| API + agents | Render (free Docker web service) | `apps/api/Dockerfile.demo`, `render.yaml` |

The browser only talks to the Vercel origin. Next.js rewrites `/api/*` to the API
(`apps/web/next.config.ts`), so the session cookie is first-party and no CORS setup is needed.

## Demo mode vs the full stack

The hosted API runs with `GIGBID_MCP_MODE=inprocess`: the agents call the in-process tool layer
(`evals/inprocess_mcp.py`), which has the same tool names, result shapes and idempotent write
behaviour as the three MCP servers. It is backed by the synthetic data in `data/`, so the API needs
no Postgres, Redis or MCP servers. Runs and approvals are kept for the life of the process; a
restart clears them (the reviewer account is re-created from env on start). Human approval via
`interrupt()` is unchanged, and nothing is ever sent to a real marketplace.

The full stack (GigSim, three MCP servers over Streamable HTTP, Postgres checkpoints, Phoenix)
runs locally with `make up && make seed && make dev`.

## 1. API on Render

1. Render dashboard -> New -> Blueprint -> pick this GitHub repository. Render reads `render.yaml`.
2. Fill in `REVIEWER_EMAIL`, `REVIEWER_PASSWORD` and `WEB_ORIGINS` (the Vercel URL from step 2;
   it can be added after the first deploy). `JWT_SECRET` is generated by Render.
3. Wait for the build, then open `https://<service>.onrender.com/health`; it should return
   `{"ok": true, ...}`.

The free plan sleeps after 15 minutes idle; the first request after that takes about a minute.

## 2. Web UI on Vercel

From `apps/web`:

```sh
npx vercel login
npx vercel link            # create the project; root directory = apps/web
npx vercel env add API_INTERNAL_URL production     # https://<service>.onrender.com
npx vercel env add NEXT_PUBLIC_API_URL production  # /api
npx vercel deploy --prod
```

Or in the Vercel dashboard: import the repository, set **Root Directory** to `apps/web`, and add
the same two environment variables before the first deploy. Both are read at build time, so
redeploy after changing them.

## 3. Check

- `https://<vercel-app>/api/health` returns the API health JSON.
- Sign in at `https://<vercel-app>/onboarding` with the reviewer account.
- Inbox -> open a job -> Analyze -> the run timeline streams, and a bid-worthy job stops at the
  approval panel.

Reviewer credentials go in the private Classroom comment only, never in the repository.
